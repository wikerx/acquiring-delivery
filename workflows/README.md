# 工作流总览

V2 从 [Desktop 使用说明](../README.md) 开始，阶段及审批规则见 [V2 需求生命周期](requirement-lifecycle.md)。以下为 V1 工作流总览，保留用于追溯。

## 文档目的

串联 Acquiring Platform 需求接收、确认、设计、开发、测试、审查、发布和关闭流程，说明人工确认、Codex 执行边界、并行和串行规则。

## 标准流程

需求接收 -> 需求确认 -> 技术设计 -> 开发 -> 测试 -> 审查 -> 发布 -> 关闭

## 阶段说明

| 阶段 | 主要动作 | 人工确认 | Codex 可执行 | 串并行规则 |
|---|---|---|---|---|
| 需求接收 | 记录原始需求、范围、待确认问题 | 需求来源和敏感信息脱敏 | 创建和维护需求文档 | 串行 |
| 需求确认 | PRD、业务规则、验收标准 | 必须确认 | 整理文档、追踪 open questions | 串行；确认前禁止开发 |
| 技术设计 | 影响分析、接口、数据库、权限、配置、时序 | 必须确认 | 只读扫描代码，维护设计文档 | 串行；确认后才开发 |
| 开发 | 后端、前端、SDK 按需开发 | 公共变更需确认 | 在批准范围内修改代码 | 后端/前端/SDK 可并行，但公共文件必须串行 |
| 测试 | 执行测试、记录缺陷和回归 | 阻塞缺陷处理需确认 | 执行命令、记录结果、按确认范围修复 | 缺陷修复和回归串行 |
| 审查 | 代码审查、风险复核 | 高风险问题需确认 | 只读审查，必要时按确认范围修复 | 通常串行 |
| 发布 | 部署计划、配置、发布清单、回滚 | 必须确认 | 准备发布资料 | 生产操作必须人工执行 |
| 关闭 | 状态归档、发布说明和遗留问题 | 必须确认 | 更新交付文档 | 串行 |

## 可并行步骤

- 技术设计确认后，后端、前端、SDK 可在独立 Worktree 中并行，前提是接口契约稳定且不并行修改公共 DTO、枚举、数据库实体和根配置。
- 测试用例设计可与开发并行，但测试结论必须基于实际完成的代码。
- 发布资料草案可与测试后期并行，但发布确认必须在测试通过之后。

## 必须串行步骤

- 需求确认必须早于技术设计确认。
- PRD 和技术设计确认必须早于开发。
- 接口契约稳定必须早于前端联调和 SDK 开发。
- 数据库、生产配置和权限发布必须经过人工确认后执行。
- 缺陷修复必须早于对应回归结论。

## 生产操作禁止 Codex 自动执行

Codex 禁止自动执行：

- 推送或合并生产分支。
- 生产发布、回滚、数据库操作和生产配置变更。
- 强制推送、删除远端分支或改写公共历史。
- 提交密钥、Token、证书、真实商户配置和生产凭证。

## 完成标准

- 每个需求可从 `STATUS.md` 追踪到当前阶段、状态、交付物和下一步。
- 所有不确定内容进入 open questions。
- 发布前质量门禁、测试、安全和回滚资料齐备。
