# Definition of Ready

## 文档目的

定义需求进入开发前必须满足的准备条件。

## 检查清单

| 检查项 | 标准 | 是否必需 |
|---|---|---|
| 原始需求完整 | 来源、背景、提出人、目标用户和范围已记录 | 是 |
| 业务规则确认 | 金额币种、状态、幂等、渠道、安全和异常规则已确认 | 是 |
| 验收标准明确 | 每个关键需求可执行、可观察、可判定 | 是 |
| 影响范围完成 | 后端、前端、SDK、数据库、Redis、RocketMQ、任务、权限、配置、发布回滚均已判断 | 是 |
| API 方案确认 | 内部接口、OpenAPI、前后端契约和错误码已确认 | 按需 |
| 数据库方案确认 | 表、字段、索引、迁移和回滚方案已确认 | 按需 |
| SDK 适用性确认 | 仅对外接口或协议变化时创建 SDK 任务 | 是 |
| 阻塞问题清理 | 无未解决阻塞；未确认内容进入 open questions | 是 |
| 测试条件具备 | 测试环境、数据、命令和人工验收方式明确 | 是 |
| 分支和任务明确 | Codex 任务、分支、Worktree 和交接方式明确 | 是 |

## 人工确认

DoR 必须由需求负责人、技术负责人和测试负责人确认。涉及安全、数据库、生产配置、OpenAPI 或 SDK 时，对应负责人也必须确认。

## 完成标准

- `STATUS.md` 已更新为 `待开发`。
- DoR 检查项无阻塞。
- PRD 和技术设计已确认。
- Codex 才允许在批准范围内修改业务代码。
