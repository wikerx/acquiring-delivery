# 需求生命周期

## 文档目的

定义 Acquiring Platform 需求从草稿到关闭的状态、进入条件、退出条件、允许流转、必需文档、人工确认点和 Codex 可执行边界。

## 适用范围

适用于 `acquiring-delivery/requirements/REQ-XXX/` 下的全部需求。不创建具体业务需求时，只维护模板和流程。

## 状态流转总览

草稿 -> 待澄清 -> 需求确认中 -> 需求已确认 -> 技术设计中 -> 技术设计已确认 -> 待开发 -> 开发中 -> 待提测 -> 测试中 -> 测试不通过 -> 开发中

测试中 -> 测试通过 -> 待发布 -> 发布中 -> 已发布 -> 已关闭

任意未开发状态可在人工确认后流转到已取消；已发布后如无需继续跟踪，流转到已关闭。

## 状态规则

| 已取消 | 人工确认需求取消 | 记录取消原因 | 无 | `STATUS.md`、`open-questions.md` 按需 | 是 | 禁止修改业务代码 |

## 人工确认点

- PRD、业务规则、验收标准确认。
- 技术设计、接口契约、数据库、权限和配置方案确认。
- 公共 DTO、枚举、数据库实体、根配置、OpenAPI 协议和 SDK 兼容性变更确认。
- 测试不通过后的修复范围确认。
- 发布、回滚、生产配置和数据库操作确认。

## Codex 禁止修改业务代码的状态

草稿、待澄清、需求确认中、需求已确认、技术设计中、技术设计已确认、待开发、待提测、测试通过、待发布、发布中、已发布、已关闭、已取消。

测试中仅允许只读定位；测试不通过仅允许在人工确认的缺陷范围内修复。

## 完成标准

- 状态名称与 `STATUS.md` 保持一致。
- 未确认内容进入 `open-questions.md`。
- PRD 和技术设计确认前禁止开发。
- SDK 仅在对外接口或协议变化时创建任务。
