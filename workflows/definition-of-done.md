# Definition of Done

## 文档目的

定义需求进入发布或关闭前必须满足的完成条件。

## 检查清单

| 检查项 | 标准 | 是否必需 |
|---|---|---|
| 代码完成 | 已按确认范围完成后端、前端、SDK 适用任务 | 是 |
| 单元测试完成 | 修改业务规则、高风险链路和 SDK 公共 API 已补充测试 | 是 |
| 构建通过 | 后端 Maven、前端 typecheck/build、SDK test/package 按影响范围执行 | 是 |
| 前后端契约一致 | 接口路径、字段、枚举、状态、错误码和权限一致 | 按需 |
| 数据库脚本完整 | SQL 草案、迁移、校验和回滚完整 | 按需 |
| 权限和配置完整 | 菜单、按钮、接口权限、Nacos、env、渠道、SDK 配置已确认 | 按需 |
| 测试和回归通过 | 测试结果和回归结果来自本轮真实执行或人工验收 | 是 |
| 安全检查完成 | OpenAPI、签名、加密、防重放、敏感日志、前端存储、SDK 密钥规则已检查 | 是 |
| 发布和回滚方案完整 | 部署计划、配置清单、发布清单、回滚方案已确认 | 是 |
| 文档更新完成 | PRD、设计、变更清单、测试、发布说明和 `STATUS.md` 已更新 | 是 |

## 人工确认

发布前必须由需求、技术、测试和发布负责人确认。涉及生产配置、数据库、安全或 SDK 版本时，对应负责人必须额外确认。

## 完成标准

- `STATUS.md` 记录 [V2 生命周期](requirement-lifecycle.md) 中的真实阶段及状态。最终验收通过后准备发布，发布准备经用户批准才进入 `待发布`。
- 未执行项和失败项没有被写成通过。
- 发布风险有明确接受人。
