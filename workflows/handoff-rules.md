# 阶段交接规范

## 文档目的

定义需求各阶段之间交接时必须说明的确认内容、交付文件、未完成内容、阻塞、风险、测试结果和下一阶段允许范围。

## 通用交接字段

| 字段 | 要求 |
|---|---|
| 已确认内容 | 只写已由文档、代码、配置或人工确认支持的结论 |
| 交付文件 | 列出文件路径和状态 |
| 未完成内容 | 写明原因、负责人和预计处理阶段 |
| 阻塞问题 | 同步到 `open-questions.md` |
| 风险 | 标注影响范围和风险等级 |
| 测试结果 | 记录本轮真实命令或人工验证；无则写“未执行” |
| 下一阶段允许范围 | 明确可读、可改仓库和禁止项 |

## 需求到技术设计

- 已确认内容：PRD、业务规则、验收标准、范围和不处理项。
- 交付文件：`original-requirement.md`、`prd.md`、`business-rules.md`、`acceptance-criteria.md`、`open-questions.md`、`STATUS.md`。
- 下一阶段允许范围：只读代码和配置，修改 `acquiring-delivery` 设计文档；禁止修改业务代码。

## 技术设计到后端开发

- 已确认内容：影响后端模块、接口契约、数据库、权限、配置、状态、幂等、安全和测试策略。
- 交付文件：`impact-analysis.md`、`technical-design.md`、`api-contract.yaml`、`database-design.md`、`permission-design.md`、`configuration-design.md`、`implementation-plan.md`。
- 下一阶段允许范围：仅在已确认模块和分支内修改后端代码；公共 DTO、枚举、实体和根配置变更需再次确认。

## 技术设计到前端开发

- 已确认内容：目标应用、页面、路由、菜单、按钮权限、接口契约、错误码和展示口径。
- 交付文件：PRD、技术设计、接口契约、权限设计、前端任务。
- 下一阶段允许范围：仅修改目标前端应用和共享包中已确认范围；禁止伪造后端字段、权限或接口。

## 后端到前端接口交接

- 已确认内容：接口路径、方法、认证、权限、请求响应、错误码、枚举、状态、金额币种、幂等和安全处理。
- 交付文件：`api-contract.yaml`、后端任务、变更清单、后端测试结果。
- 下一阶段允许范围：前端按契约联调；契约变更必须回到后端和技术设计确认。

## 后端、前端到测试

- 已确认内容：代码完成、自测完成、构建或 typecheck/build 结果、已知风险。
- 交付文件：变更清单、后端/前端/SDK 任务、测试计划、测试用例。
- 下一阶段允许范围：测试执行和缺陷记录；缺陷修复需确认范围后进入修复。

## 测试到发布

- 已确认内容：测试通过、回归通过、未修复缺陷风险已确认。
- 交付文件：`test-result.md`、`defect-list.md`、`regression-result.md`、`code-review.md`。
- 下一阶段允许范围：准备发布资料；禁止 Codex 执行生产发布、数据库和生产配置操作。

## 缺陷修复后的回归交接

- 已确认内容：缺陷编号、根因、修复范围、影响范围和回归建议。
- 交付文件：缺陷清单、变更清单、修复分支、回归结果。
- 下一阶段允许范围：测试只回归确认范围；如发现外溢影响，回到技术负责人确认。

## 完成标准

- 交接不依赖聊天上下文。
- 阻塞和风险有文件化记录。
- 下一阶段不会越权修改。
