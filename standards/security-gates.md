# 安全门禁

## 需求分析阶段

- 识别是否涉及商户 OpenAPI、支付、代付、退款、渠道回调、商户通知、收银台、SDK、后台权限或敏感数据。
- 明确敏感数据类型：卡号、CVV、JWT、Token、API Key、merchantKey、私钥、公钥、身份证件号、银行卡号、手机号、邮箱、明文报文。
- 未确认安全口径必须进入 open-questions。

## 技术设计阶段

- OpenAPI 必须说明认证、请求解密、参数校验、防重放、响应加密、错误处理和日志脱敏。
- 渠道回调必须说明签名校验、IP 白名单、原文保存、幂等和状态流转校验。
- 内部接口必须说明内部调用边界，不能只因路径是 `/internal/**` 就视为安全。
- 前端必须说明敏感数据展示、日志、本地存储和错误提示边界。
- SDK 必须说明密钥加载、JWT、加解密、日志脱敏和示例密钥策略。

## 后端开发阶段

- 禁止绕过 `@VerificationAndProcessing` 新增商户对外 API。
- 成功响应的商户 OpenAPI `data` 必须加密，禁止返回敏感明文。
- 禁止记录完整卡号、CVV、私钥、JWT、Token、API Key、merchantKey、完整敏感报文。
- 生产或 UAT 环境不得启用本地模拟支付、Noop MQ、Noop Channel、Redis 防重放降级、明文密钥、默认密码或测试商户密钥。
- 支付写操作必须具备幂等和状态合法性校验。

## 前端开发阶段

- 不在浏览器日志输出敏感字段和完整接口响应。
- 不把卡信息、CVV、Token、商户密钥、解密报文写入 `localStorage`、`sessionStorage`、IndexedDB 或 Cookie。
- 不伪造权限、菜单和后端字段绕过安全控制。
- 收银台改动必须确认桌面端和移动端不会暴露敏感字段。

## SDK 开发阶段

- 不写死商户密钥、JWT secret、私钥、公钥或生产地址。
- 示例配置必须使用脱敏或测试值。
- 签名、JWT、AES、RSA、密钥加载、日志脱敏修改必须增加测试。
- 日志脱敏测试必须覆盖商户号、卡号、账户号、Token、key 等场景。

## 测试阶段

- 安全测试必须包含正常请求、签名失败、JWT 过期、重放请求、解密失败、非法参数、重复回调和敏感日志检查。
- 不能因为本地环境缺少中间件就跳过安全风险记录。
- 失败项必须记录影响范围和建议负责人。

## 发布阶段

- 发布资料不得包含敏感密钥、生产凭证或明文敏感报文。
- 发布前确认生产安全配置、密钥来源、防重放、回调白名单、日志级别和监控告警。
- 安全门禁未通过时不得给出无风险发布结论。
