# 开发门禁

## 需求分析阶段

准入：

- 需求来源、目标用户、业务目标已明确。
- 涉及支付、代付、退款、结算、风控、渠道、商户 OpenAPI、收银台或 SDK 的范围已标记。
- 未确认的问题已进入 `platform/baseline-open-questions.md` 或 `open-questions/`。

准出：

- 不擅自扩展业务范围。
- 已标明影响仓库：`acquiring-orchestration`、`acquiring-frontend`、`acquiring-openapi-java-sdk`、`acquiring-delivery`。
- 已确认不处理项和人工确认项。

## 技术设计阶段

准入：

- 已读取现有代码、配置、README、AGENTS 和相关测试。
- 所有职责判断都有代码路径或配置依据。

准出：

- 已说明模块边界、分层方案、数据流、状态流、幂等点和安全边界。
- 未经确认不升级依赖、不变更公共接口、不移动目录。
- 技术方案中的不确定内容已记录为待人工确认。

## 后端开发阶段

准入：

- 使用 JDK 17。
- 已确认受影响 Maven 模块和依赖关系。
- 已扫描现有 `api`、`application`、`service`、`mapper`、`dto`、`vo`、`entity`/`DO`、`converter`、测试类。

准出：

- 修改保持最小范围。
- Controller/API 不承载核心业务规则。
- 能使用 MapStruct 时优先使用。
- 金额、汇率、费率不使用 `float` 或 `double`。
- 写操作已考虑幂等；状态变更已校验合法流转。
- 未硬编码渠道名称，未记录敏感明文。
- 已执行对应模块编译和测试，或如实记录无法执行原因。

## 前端开发阶段

准入：

- 已确认目标应用：`apps/admin-system`、`apps/merchant-portal` 或 `apps/hosted-checkout`。
- 已确认接口、枚举、状态、错误码来源。
- 已确认现有菜单、权限、路由和状态管理方式。

准出：

- 未伪造后端字段、接口、菜单、权限或业务指标。
- 公共枚举和类型不在页面组件中重复定义。
- 不升级依赖，不做无关页面重构。
- 收银台改动已兼顾桌面端和移动端。
- 已执行对应 `typecheck`、`build`；如存在 lint 脚本则执行 lint，否则记录缺口。

## SDK 开发阶段

准入：

- 已确认 SDK 对外公共类、方法、字段和模型影响范围。
- 已确认 SDK 保持 JDK 1.8 / Java 8 编译目标，以兼容更多商户服务端运行环境。
- 已确认配置仍遵循 `merchant-config.properties` 方式。

准出：

- 保持向后兼容；破坏性修改已明确标识。
- 未写死商户密钥、JWT secret、私钥、公钥或生产地址。
- 签名、JWT、AES、RSA、密钥加载、日志脱敏修改已增加测试。
- 示例代码不包含真实密钥。
- 已执行完整测试和打包，或记录失败原因。

## 测试阶段

准入：

- 已列出受影响模块、核心链路和风险点。
- 已准备单元测试、集成测试、回归测试或人工验证清单。

准出：

- 测试命令、范围、结果和失败原因已记录。
- 不得用历史测试报告替代本轮验证。
- 未通过项已标明风险和建议归属。

## 发布阶段

准入：

- 需求状态、技术方案、测试报告、发布计划已更新。
- 版本号、Tag、变更记录、部署环境和回滚方案已确认。

准出：

- 发布资料不包含敏感密钥或明文敏感报文。
- 发布影响范围、检查项、回滚条件、监控指标已记录。
- 未确认项不得进入发布结论。
