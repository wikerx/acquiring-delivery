# 产品需求文档

## 文档目的

将原始需求整理为可确认、可设计、可验收的产品需求。

## 填写责任

产品或需求负责人主写；业务、研发、测试、安全和发布相关负责人确认。

## 输入资料

- `original-requirement.md`
- `business-rules.md`
- `acceptance-criteria.md`
- `open-questions.md`
- 既有平台基线和服务边界文档。

## 必填内容

- 背景、目标、目标用户和业务价值。
- 需求范围和不处理范围。
- 影响系统：管理系统、商户系统、收银台、OpenAPI、SDK、后端服务、数据库、中间件、配置和发布。
- 业务流程、状态变化、金额币种口径、安全要求、权限要求和异常处理。
- 明确 SDK 是否适用；仅对外接口、协议、模型、签名/加密、配置或示例变化时创建 SDK 范围。
