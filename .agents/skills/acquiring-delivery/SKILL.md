# Acquiring Delivery

从当前交付仓库根目录读取 [生命周期](../../../workflows/requirement-lifecycle.md) 和 [台账协议](references/ledger.md)。业务任务再按 [平台基线](../../../platform/current-baseline.md) 路由到目标仓库。保留用户此前按 Word 落地的编码规则、仓库级 Skill、质量检查和前端既有组件、权限与交互。

## 处理请求

1. **创建。** 定位或初始化用户指定的私有 Git 台账。按 [模板索引](../../../templates/README.md) 分配稳定的 `REQ-XXX`，先记录原始需求与状态，启动产品经理。演练只接触用户指定的合成台账和夹具。
2. **查看或恢复。** 重读台账 Git 版本、状态、决定和候选版本。查看始终只读。恢复只执行记录中已授权且仍有效的工作。待审批时显示审批号、交付物和动作，然后结束本轮。
3. **批准或驳回。** 只处理当前用户对已提交候选的明确决定。按生命周期校验审批号、产物版本、拟进入阶段和授权范围。同步提交状态和决定后再执行获准动作。阻塞结果、歧义、冲突或过期审批保持原位，等同一用户澄清。重复决定按台账返回既有结果。
4. **变更或缺陷。** 记录影响、回流点、失效的审批和证据。用户明确修订范围后再执行，重新提审。发现新增契约、权限、资金口径、迁移或业务范围变化时回适用阶段。

## 委派与收口

- 在获准的阶段调用 `.codex/agents/` 中的对应 Agent。提供需求号、获批输入、候选版本、可访问目录、允许操作、交付格式和验证范围。同一轮只执行获准的一个阶段。独立测试、Code Review、验收各启动新实例。当前项目缺少该独立角色时，记录阻塞并停止，不代签结果。
- 主会话是台账唯一写入者。收集 Agent 返回的草案和证据，验证事实、提交和权限范围，按模板写入私有台账。角色不得自行启动下一阶段或更新审批。
- 业务仓库默认只读。业务文件写入须同时满足开发阶段有效批准、目标仓库自身规则及指定 Worktree 的实际权限；仅在批准范围内工作。出于隔离，不能获得适用权限时保留阻塞。交付仓库只存公开规范和脱敏演练。
- 阶段提交要显示交付物、版本、风险与阻塞、测试证据或未覆盖项，以及下一阶段拟执行范围。准出完备后设置唯一审批号并结束本轮，等待用户答复。
